# Review: Forever Tweaks against Blizzard's sources (November 2026)

A one-off review of version 1.1.1. It answers two questions:

1. Which features can players already set in the game's own Options, so they may not need to be in the addon?
2. Does the code follow the practices of Blizzard's own UI code?

No code was changed for this review.

**Follow-up in 1.2.0:** Status Text and Mute Error Speech were removed. Their settings live in the game's Options, and the console variables stay as each player left them. FPS & Latency, View Distance, Rotate Minimap, Error Catcher, Layer Info and Button Bag were kept as they are.

**Follow-up in 1.4.0:** View Distance & Detail was removed too: the game's Graphics options and console variable editors set those values, and each player's stay as they left them. This document is otherwise a snapshot of the 1.1.1 review.

## Sources

- **community.developer.battle.net/documentation** covers Blizzard's *web* APIs only, such as character profiles and auctions over HTTPS. It has nothing on the in-game Lua or UI API, so it can't be used to judge addon code. See the end of `forever-api.md`.
- **Gethe/wow-ui-source, `forever` branch.** This is Blizzard's own interface code for the Forever client and the closest thing to official in-game documentation. Every finding below was checked there. Paths are under `Interface/AddOns/`.

### Open question

**Resolved by 1.2.0:** both modules were removed, so this check is no longer needed. It's kept as the record of why.

Does Forever keep `statusTextDisplay`, `statusText` and `Sound_EnableErrorSpeech` after a full logout? If it does, the game's own option does everything Status Text and Mute Error Speech do, and both modules can go. If it doesn't, give each module's header a one-line reason, as Rotate Minimap's header has ("The game resets this at login").

To check, for each module:

1. Turn the module off in Forever Tweaks.
2. Set the option in the game's Options.
3. Log out to the character screen and log back in.
4. Run `/dump C_CVar.GetCVar("statusTextDisplay")`, `/dump C_CVar.GetCVar("statusText")` and `/dump C_CVar.GetCVar("Sound_EnableErrorSpeech")`.

## 2. Best-practice findings

Most important first.

### 1. View Distance changes the player's graphics as soon as the addon is installed

`Modules/Graphics/ViewDistance.lua` is on by default, with `farclip = 7000`. Forever's default is 1000, and `forever-api.md` says values like 7000 are "the likeliest cause of stutter". The module also replaces whatever the player picked with the game's View Distance slider.

- Core/CVars.lua follows later changes the player makes in Options, so the player can undo it.
- But the first impression is a heavier game that the player never asked for.

Suggestion: default the module to off, or write a CVar only once the player has moved that slider.

### 2. A raw timer in a module

`Modules/Map/ButtonBag.lua:199` (`requestLayout`) calls `C_Timer.After` directly. CLAUDE.md says modules must not do this: the timer is not owned by the module, isn't stopped when the module turns off, and isn't timed by the Profiler. `M:After(0, ...)` does the same job within the rules.

`Settings/Kit.lua` (now `UI/Kit.lua`) and `Settings/Modules.lua` also call `C_Timer.After` directly. They are settings-UI code, not modules, so this matters less, but it is still inconsistent.

### 3. Button Bag replaces methods on other addons' buttons

To stop addons from moving a bagged button back onto the minimap, `ButtonBag.lua:240` replaces the button's `SetPoint`, `ClearAllPoints` and `SetParent` with empty functions. The bag then moves the button itself through `getmetatable(UIParent).__index` (line 70). The methods are put back on release (line 251), and protected frames are never taken.

This works, but it is the riskiest pattern in the addon: an addon that kept its own reference to one of those methods, or a button that becomes protected later, will behave unexpectedly.

Where LibDBIcon is loaded, its own calls could cover the common case without replacing anything:
- `lib:Hide(name)` hides an addon's minimap button.
- `lib:AddButtonToCompartment(name)` adds it to the game's addon menu.

Methods would then only need replacing for buttons that don't use LibDBIcon.

### 4. Minimap Button edits a table owned by Blizzard

The game has no way to unregister from the Addon Compartment, so `Modules/Map/MinimapButton.lua:91` removes Forever Tweaks' entry from `AddonCompartmentFrame.registeredAddons` itself.

- LibDBIcon does the same, and the compartment isn't secure code, so there's no taint risk.
- It does depend on how Blizzard has written that list, so it is worth re-checking whenever Forever updates `Blizzard_Minimap/Camelot/AddonCompartment.lua`.

No change needed.

### 5. Error Catcher takes over the error handler before it knows whether it's on

`Modules/Tools/ErrorCatcher.lua:89` calls `seterrorhandler` when the file loads, before saved variables say whether the module is on. If it turns out to be off, any errors held in the meantime are passed on and the previous handler is put back. That is correct; the only cost is that BugSack sees errors from that moment slightly late. No change needed.

### 6. TOC metadata

Midnight-era clients read optional `.toc` fields that this addon doesn't use yet:
- `## Category`, which groups addons in the addon list.
- `## AddonCompartmentFunc`, which adds an entry to the addon menu with no code.

The second doesn't fit, because the compartment entry is added in code on purpose so players can switch it on and off. Before adding `## Category`, check in game that Forever's addon list uses it.

### Already in line with Blizzard's own code

- **Events:** everything goes through one shared frame, and each handler runs under `securecallfunction`, so one error can't stop the others.
- **Combat:** CVar writes wait until combat ends (`ns:AfterCombat`).
- **CVars:**
  - A change the player makes in the game's Options is followed, not fought.
  - Turning a module off restores the original values (Core/CVars.lua).
  - CVars the client doesn't have are skipped (`GetCVar` returns nil).
- **Settings:** the current APIs are used: `Settings.RegisterCanvasLayoutCategory` / `RegisterAddOnCategory`, `MenuUtil` context menus, `WowStyle1DropdownTemplate`, `MinimalSliderWithSteppersTemplate`.
- **Edit Mode:** hooked with `hooksecurefunc`, and `ClearSelectedSystem` is only called out of combat.
- **Secret values:** GUIDs and frame strata are checked with `issecretvalue` before they're used.
- **Frames:** windows close with Escape (`UISpecialFrames`).
- **Globals:** the only ones are `ForeverTweaksAPI`, the saved variables and the slash commands. The public API returns copies and is read-only.
